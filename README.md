# lofter-tag-distiller

爬取 Lofter 某个 tag 下的文章（排除乙女向）→ 用 LLM 蒸馏成「人设 / 文风 / 桥段 / 雷点」知识库 → 根据你的想法生成一篇你想看的文章。

爬虫部分基于 [IshtarTang/lofterSpider](https://github.com/IshtarTang/lofterSpider) 逆向出的 `TagBean.search.dwr` 接口重写，并做了两点改进：

- **列表接口自带全文**，不逐篇访问帖子页，从源头避开 2026 年 Lofter 的"3 秒/篇"限流（详见其 issue #45/#47）；
- **解析器是小型分词器**而非正则切分，正文里出现 `";` 不会截断。

## 安装

**部署到新机器**（克隆即用，三步）：

```bash
git clone https://github.com/Yar1991-Translation/ele.git
cd ele
启动.bat          # Windows：自动检查环境、装依赖、构建界面并拉起 GUI
```

（非 Windows 或手动：`pip install -r requirements.txt`，前端要构建一次：
`cd frontend && npm install && npm run build`，然后 `python gui.py`。）

`.env`（登录 Cookie 与模型密钥）和 `config.yaml` 都**不在仓库里**——它们含密钥
与个人数据，每台机器各自生成：首次启动会自动弹出**四步设置向导**（验证登录 →
测试模型 → 选标签 → 跑 20 篇小样例），跟着走即可；config.yaml 缺失时会按默认值
自动生成。

依赖两样：

- **Python 3.9+**（本机 3.11 已验证）；
- **Node.js 18+**（仅用于构建界面，装一次即可，选 LTS 版：https://nodejs.org/）。

```bash
pip install -r requirements.txt   # 后端依赖
copy .env.example .env            # Windows；macOS/Linux 用 cp
```

Windows 用户也可以直接双击 **`启动.bat`**：它会检查 Python/Node、自动装依赖、构建界面并拉起 GUI。

## 配置（三步）

### 1. Lofter 登录（.env）

先确认你的登录方式对应哪个 cookie（F12 → 应用(Application) → Cookie → `https://www.lofter.com`）：

| 你的登录方式 | 对应 cookie 名 |
|---|---|
| QQ / 微信 / 微博 | **LOFTER_SESS**（最常见，HttpOnly、100+ 字节那个） |
| 邮箱 | NTES_SESS |
| 手机号 | LOFTER-PHONE-LOGIN-AUTH |
| Lofter id | Authorization |

三种填法任选其一：

- **方法 A（推荐，最省事）**：双击复制 `LOFTER_SESS` 的【值】，填 `LOFTER_COOKIE=`（只填这一个值，程序认得）；
- **方法 B（拿不准就抄全）**：F12 → 网络(Network) → 刷新 → 点任一条 `www.lofter.com` 请求 → 请求标头(Request Headers) → 整行 `Cookie:` 的值全部粘进 `LOFTER_COOKIE=`；
- **方法 C**：`LOFTER_LOGIN_KEY=LOFTER_SESS`、`LOFTER_LOGIN_AUTH=它的值`。

GUI 的「设置」页里就是第一个输入框，填法相同；第一次打开还会有四步向导带着你走。

### 2. LLM（.env）

默认火山方舟（豆包），填 `LLM_API_KEY` 和 `LLM_MODEL` 即可；DeepSeek / Kimi / 智谱等改 `LLM_BASE_URL` 就行，都是 OpenAI 兼容协议。

### 3. 目标 tag（config.yaml）

```yaml
crawl:
  tag: "你要爬的tag"     # 必填，直接写中文
  sort: "new"            # 推荐：标准翻页，上限约1099篇；超过用 date（按天回溯，慢）
  skip_img_posts: false   # 可选：爬取阶段直接跳过纯图片帖（默认由过滤层零成本排除）
  max_count: 0           # 0=不限；先小规模验证可设 20
```

其余配置（乙女向关键词表、蒸馏侧重、写作篇幅等）都在 `config.yaml`，带中文注释。

## 使用

### 方式一：图形界面（推荐）

界面为 Vue3 + Vite 工程（`frontend/`），构建产物由 Flask 托管。

**最省事**：Windows 双击 `启动.bat`（自动检查环境、装依赖、构建、拉起）。

手动启动：

```bash
pip install -r requirements.txt        # 后端依赖（含 flask）
cd frontend && npm install && npm run build && cd ..   # 构建前端（仅首次或改前端后）
python gui.py                          # 自动打开浏览器，默认 http://127.0.0.1:8765
```

改前端后刷新页面即生效（服务端已禁缓存）；开发改前端用 `python gui.py --watch`：改动 frontend/ 源码自动重建、页面自动刷新，无需手动 F5。

界面按「要做的事」分成五页，底部任务条常驻显示当前进度（切页也不会丢）：

- **总览**：素材就绪度、还差哪几步（点击直达）、最近成果与日志；没配好时会自动弹四步**设置向导**（验证登录 → 测试模型 → 选标签 → 跑 20 篇小样例）；
- **素材**：爬取 → 过滤 → 蒸馏 → 角色卡 四个步骤卡（进度、产物计数、重跑、一键全跑），下方浏览文章表（搜索 / 分类 / 结局 / 排序）、知识库与人物卡（可读可导出、人设可导入/删除）、**设定与剧情**（写作查询工具的资料来源，可上传/预览/删除）；
- **写作**：写作前先做**就绪检查**（缺素材会提前说清），选**文章类型**（单人向 / CP向 / 其他）、**CP组合**（微量 / 男女 / 男男 / 女女 / 多CP / 无CP）和**结局**（HE / BE / 开放式 / 不限），写想法点「开始写作」；文章类型选"单人向"时 CP组合强制锁定为"微量"。@角色名 可点名人物卡；想法会被拆成需求清单逐条兑现，成文文首附「想法兑现清单」验收；想法有歧义或关键细节需要拍板时，**AI 会在任务条上向你提问**（回答后继续写，超时按建议继续，每篇最多问几次）；完成后直达成果；
- **成果**：生成的文章 / 讨论记录 / 提示词分组摆放，支持搜索、删除、重命名、导出、**两篇对比**、送回润色；阅读器有字号调节、目录和阅读进度记忆；
- **设置**：一键预设档位（试跑 / 标准 / 精细）、登录与模型（带「验证登录」「测试模型」「测试其他模型」）、**模型提供商**（行式编辑器，密钥脱敏）、全部配置项（搜索 + 高级折叠 + 逐字段中文说明，团队成员也用行式编辑器增删），以及**提示词在线编辑**（带变量说明表、自动备份可回滚）。

只监听 127.0.0.1，换端口用 `python gui.py --port 9000`；不想自动开浏览器加 `--no-browser`。

### 方式二：命令行

```bash
python main.py selftest         # 离线自测解析器（不需要任何配置）
python main.py crawl            # 1. 爬取（可反复运行，断点续爬）
python main.py filter           # 2. 过滤乙女向 + LLM 分类 -> filtered.jsonl
python main.py distill          # 3. 按分类蒸馏 -> data/knowledge/分类/ 知识库
python main.py write -i "想法"  # 4. 按想法写一篇文章 -> data/output/
python main.py run-all          # 1->2->3 一键
python main.py stats            # 查看各阶段数据量
```

`write` 支持六种写作方式（GUI 写作页的"写作方式"下拉框对应同一套参数）：

```bash
# 自动生成（默认）：LLM 按想法和知识库写
python main.py write -i "雨夜重逢，要虐后甜" --type CP向 --cp 男男 --ending HE

# 关键词速写：一个关键词 + 点名人物 + 可选全员登场，剧情由 AI 结合知识库设计
python main.py write --mode quick -i "回忆" --type 单人向 --ending 开放式
python main.py write --mode quick -i "回忆" --all-roster   # 其余干员全员跑龙套客串

# 我自己写：原稿原样收进 data/output/（不做任何 LLM 处理）
python main.py write --mode self --file 我的草稿.txt

# 润色：保留你的情节与结构，只按文风知识库改进语言，不改情节与结局
python main.py write --mode polish --file 我的草稿.txt -i "对话再口语化一点"

# 扩充：以原稿情节为准，加细节扩写到目标篇幅（目标篇幅在 config.yaml 的 write.length）
python main.py write --mode expand --file 我的草稿.txt
```

`--type 单人向` 时 CP 组合强制为 `微量`；短稿可用 `--draft "..."` 内联代替 `--file`；目标篇幅、单章字数等在 `config.yaml` 的 `write:` 段（GUI 设置页同名字段）。

### 内容分级（R12 / R16 / R18 / R18G）

写作页可选**内容分级**（CLI `--rating`，config `write.rating`，默认最严的 R12），
分级作为硬性内容边界注入全部生成与审校环节（骨架/大纲/逐章/自查/末章/结局修复/
润色/团队评审），并标注在成文头部与讨论记录里：

- **R12（普遍级）**：全年龄。无露骨性描写与性暗示，亲密止于牵手拥抱；暴力死亡镜头移开；
- **R16（辅导级）**：重暴力/死亡/创伤可直白描写；性只作暗示或淡出转场；
- **R18（无限制）**：无限制成人向——露骨内容直接细致地写，不做淡出回避、
  不受文风约束；
- **R18G（无限制·残酷描写）**：在 R18 基础上血腥、猎奇、残酷细节直白细致地写。

唯一硬边界：涉及未成年人的性内容在任何模式下都禁止（年龄存疑按未成年处理）。

**分级达标自动换模型**：主模型拒写 R16+ 内容时，在「模型分配」分组里把
`rating_switch` 设为切换线（如 R16 起）、`rating_model` 填替代模型
（支持「提供商名/模型名」，提供商在「模型提供商」分组配置）。达标时写作
全流程（骨架→大纲→逐章→自查→校验，含团队润色的全员与主笔）自动改用该模型，
日志与讨论记录会注明。

**快速模式怎么用**：写作页选「关键词速写」，想法框只填一个关键词（如「回忆」），
点上方人物卡 chips 点名几个人，需要全体干员露脸就勾「全员登场」——其余干员
自动以跑龙套客串并附阵容硬性规定（仅限官方名单）。关键词太短时 AI 会先给出
2~3 个可选故事方向让你挑，再动笔。

### 写作质量约束（防复述、防平淡）

生成链路内置了两组方向相反、配合使用的硬约束：

- **防漫写**：对话与动作合计不低于四成、禁止连续 300 字无事件的心理漫写；
- **防干瘪**：每个关键转折必须有「心理落点」（此刻在想什么、身体在做什么、
  哪句话没说出口），逐章自查会补写缺失的心理描写；
- **防复述**：人物卡与知识库是边界与语感参照、不是素材库——禁止把卡片条目
  改写成介绍句；桥段库是口味参照与防雷清单、不是情节仓库——主线必须原创
  设计，化用桥段必须翻新；
- **防一笔带过**：大纲每章 beats 限 2~4 个（宁少勿多），每个 beat 在正文里
  都要写足完整场景，骨架关键场面必须写出「怎么发生的」。

逐章/自查是重活：flash 级模型容易写得平，效果不满意时在「模型分配」里给
`write_chapter` / `write_revise` 换更强的模型或跨提供商交叉对照。

首次建议：`max_count: 20` 小规模跑通全流程，再放大。GUI 与 CLI 完全等价（GUI 就是调用同一个 main.py），混用没问题。

## 多提供商与逐步模型分配（交叉对照）

`.env` 里那组 `LLM_BASE_URL / LLM_API_KEY / LLM_MODEL` 是**主提供商**。要多请几家模型：

- **GUI**：设置页 → 「模型提供商」分组 → 添加（名称 / 接口地址 / 密钥，密钥在界面脱敏显示）；
- **手改 config.yaml**：

```yaml
providers:
  - name: deepseek
    base_url: https://api.deepseek.com/v1
    api_key: sk-xxx
```

之后所有模型配置项都能写两种引用：纯模型名（`mimo-v2.6-pro`，走主提供商）或 **`提供商名/模型名`**（`deepseek/deepseek-chat`，走指定提供商）。「设置」页的「测试其他模型」输入框可以单独验证任一引用的连通性。模型引用写错提供商名时程序会警告并按默认提供商处理。

**每个阶段都能独立配模型**（「模型分配」分组，留空 = 主模型）：

| 配置项 | 管什么 |
|---|---|
| `filter` / `distill_map` / `distill_reduce` / `character_cards` | 过滤、蒸馏、角色卡 |
| `write_outline` | 需求拆解、想法澄清提问、故事骨架、分章大纲 |
| `write_chapter` | 逐章正文（含过短重写） |
| `write_revise` | 章节自查修订、末章统筹、结局修复 |
| `bible_update` | 连续性档案提取 |
| `ending_check` | 结局走向校验（只判定不改稿） |
| `idea_check` | 想法兑现校验（只判定不改稿） |
| `polish` | 润色方式 |
| `team.editor_model` / `team.agents[].model` | 团队润色的主笔与成员 |

推荐玩法——**写与改用不同提供商的模型交叉对照**：逐章用 A 家写、自查/校验用 B 家改；
团队润色给三位成员各配一家的模型、主笔再配一家，评审讨论就是真·多模型交锋。
每次运行结束会按模型分列打印 token 用量。

## 去AI味规范（Humanizer skill）

写作链路全链路可注入 **Humanizer v4.1 去AI味规范**（规则文件在 `skills/humanizer/`，整合自 stop-slop、Humanizer-zh、oh-story-claudecode 等开源项目与真人众测信号）：
逐章生成、自查修订、末章统筹、结局修复、润色、团队评审与主笔修订都会遵守。
设置页「写作」分组 → **去AI味规范** 三档：

- **精简（默认）**：注入核心规则卡（`skills/humanizer/core.md`，三毒判定、一级禁用词、标点禁令等），每次调用约多 5K token；
- **完整**：注入 SKILL.md 全文 + 禁用词表 + 结构问题清单，约多 30K token，慎用；
- **关**：不注入。

## 设定/剧情库与写作查询工具

`data/lore/` 收**你认可的硬设定**：世界观、组织、时间线、剧情梗概（.md/.txt，支持子目录）。
GUI 素材页有「设定与剧情」标签页可上传/预览/删除。

**骨架与大纲也按需读取**（「骨架大纲按需读素材」，默认开）：设计阶段不整段注入知识库和配角人物卡，而是给模型一份文件索引（知识库文件+人物名单+设定文件），由它用查询工具按需读取——单次请求体积约减半，慢端点更稳；主役与重要档人物卡仍整卡在场。
开启设置页的「**写作前可查资料**」（默认开）后，AI 逐章动笔前可以按需**查询**：
可查清单（人物卡名单 + lore 文件列表）会写进每章的提示词，模型输出查询 JSON 即可拿到
某张人物卡的全文（预载的可能被截断过）或某份设定文件的细节，查完再落笔；
最多 `query_rounds` 轮（默认 2），每条结果上限 `query_char_limit` 字（默认 4000）。
人物卡不用放进 lore——「人物卡」标签页里的官方卡与蒸馏卡本来就都可查。

## 双层人物卡：官方档案 × 蒸馏人物卡

人物分两层，互不干扰：

- **官方人物卡**（`data/personas/`）：萌百导入的档案卡 + 你的手写卡；
- **蒸馏人物卡**（`data/personas_distilled/`）：从已爬同人文**重读原文深度蒸馏**出的
  同人语境形象（含圈内自设倾向），按角色一卡。`python main.py distill-characters`
  或运行页「蒸馏角色卡」按钮触发；自动做**别名归组**（回响=卢克·埃弗利=卢克 算同一人），
  按文章集合指纹增量缓存。

写作时（运行页）可选**人物卡来源**：两者结合 / 仅蒸馏卡 / 仅官方卡；
两者结合时用**权重滑杆**分配（默认官方 30% : 蒸馏 70%）——

- 官方档案层＝事实边界：仅在与情节直接相关时作依据，**禁止正文罗列档案资料**（生日/身高/代号等）；
- 蒸馏人物卡（同人语境形象）＝塑造依据：正文人物形象以此层为主；
- 权重决定主从（≥70 官方主导 / ≤30 蒸馏主导 / 中间均衡互校）。

## Agent 团队润色（多模型讨论）

写作方式选「**团队润色**」时，多位"编辑"Agent 会对文章进行多轮评审与讨论：
每轮全体成员各评审一次（能看到彼此意见，可补充反驳），主笔汇总产出修订稿，
修订稿进入下一轮，跑满轮数出终稿；完整讨论记录与终稿一并存入 `data/output/`。

- **成员配置**（`config.yaml` 的 `team:` 段或 GUI 设置页「团队润色」分组）：
  每位成员可设 **名称 / 模型 / 思考强度（关·低·中·高）/ 职责视角**；
  model 留空 = 全员使用主模型（即同一模型互相讨论）；
- **思考强度**需模型支持思考模式（如豆包 seed 思考版），不支持时自动回退普通调用；
- 轮数默认 1（GUI 设置页可调 1~5 轮），成员默认 3 位（文风编辑 / 人设与OOC纪检 / 读者代表），可增删改。

## 本地角色人设导入

把自己写的角色人设带进写作环节（优先级**高于**蒸馏知识库，冲突时以人设为准）：

- **GUI**：素材页 → 人物卡 → 「导入」选择 .md/.txt 文件（可多选）；
- **CLI**：`python main.py personas import <文件或文件夹>`，`personas list` 查看，`personas remove <文件名>` 删除；
- **手动**：把 .md/.txt 直接丢进 `data/personas/`。

文件格式：每个一级标题（`# 角色名`）是一个角色，标题下写该角色的人设（性格、说话方式、关系、背景等）；
没有一级标题的文件整体算一个角色（名字取文件名）。导入后五种写作方式（自动生成/我自己写/润色原稿/扩充原稿/团队润色）都会遵循；
人设内容只读不写，导入后不会被程序改动。

**@ 点名与出场比例**：在想法或原稿里写 `@角色名` 引用人物卡（GUI 写作页上方有点击插入的标签）——
被点名的角色只读被点中的人设卡，未点名的其余人设不生效；不写 @ 则全部人设生效。
可以附加出场比例：`@沈回:微量`、`@沈回（主役）`，档位从低到高为
**跑龙套（一两个镜头）→ 微量（少量点缀）→ 配角（默认，有明确戏份）→ 重要（关键配角）→ 主役（贯穿全程）**，
同一角色出现多次取最高档；模型会按点名处的剧情定制该角色的出场与刻画。

## 工作原理

```
crawl    TagBean.search.dwr 按批(100)拉列表。new 排序用最后一条的 publishTime
         做游标往前翻（上限约1099篇）；date 排序按天回溯窗口，可突破上限；
         请求间隔随机 3.5~6s；每批落盘，断点续爬；可疑响应自动转储 raw/
         -> data/posts/posts.jsonl（结构化全文）+ txt 备份
filter   关键词层（乙女向/梦女/女主...，config 可改）直接排除；
         剩余文章一次 LLM 调用完成乙女向判定 + 文章分类：
         文章类型(单人向/CP向/其他) × CP组合(微量/男女/男男/女女/多CP/无CP)
         × 结局(HE/BE/开放式/未知/不适用)，单人向强制 CP组合=微量
         -> filtered.jsonl；被排除的进 excluded.jsonl 可人工复查
distill  每篇提炼（人设/文风/桥段/金句/雷点，结果缓存，重跑只算增量）
         -> 按「文章类型·CP组合」分组合并（如 CP向·男男、单人向·微量）
         -> data/knowledge/<分类>/ 下各生成四份知识库 markdown
write    目标类型(默认 config，可用 --type/--cp/--ending 覆盖) +
         你的想法 -> 拆成需求清单（点名情节/基调/禁忌，全程逐条兑现）
         -> 取对应分类的知识库（无专属库时回退：同类型 -> 全部）
         -> 故事骨架 -> 分章大纲（需求分配到章，安排打进日志可早停）
         -> 逐章生成（带前情、全篇章节表与连续性档案）
         -> 末章统筹 -> 结局校验（不符自动修复一次收尾，仍不符才在文首标注）
         -> 想法兑现清单（文首逐条验收）-> data/output/
         全程可向你提问（GUI 在任务条上答，命令行在终端答，无人值守按建议继续）
```

LLM 每次运行结束会打印 token 用量。`filter` 的判定结果和 `distill` 的单篇提炼都有缓存，改配置重跑不会重复花钱。

## 常见问题

- **爬到 0 篇**：多半是 cookie 失效（重新复制）或 tag 写错；程序会自动在"原文/URL 编码"两种参数形式间切换重试。
- **触发限流**：程序会自动退避 10 分钟后原地重试；如果频繁触发，把 `config.yaml` 里 `request_interval_min/max` 调大。
- **tag 超过 1099 篇**：`sort: new` 只能拿到最新约 1099 篇（翻空即停）；要更早的文章把 `sort` 改成 `date`，程序会按天往回回溯（较慢，连续 `empty_day_limit` 天空窗自动停）。
- **接口又变了**：Lofter 改版时优先改 `spider/parser.py`（解析）和 `spider/dwr_client.py`（请求格式），其余层不用动。
- **乙女向误杀/漏网**：关键词在 `config.yaml` 里增删；LLM 层的判定标准在 `prompts/filter_otome.md`，`excluded.jsonl` 可复查。
- **分类不准**：分类维度定义在 `prompts/filter_otome.md` 里（文章类型/CP组合/结局），可按口味修改；判定+分类结果有缓存（v2），改完 prompt 后删除 `data/posts/filter_cache.json` 重跑 filter 才会生效。
- **写作找不到专属知识库**：写作会自动回退（同类型合并 -> 全部混合），但最好先多爬多蒸馏，让目标分类攒够素材。
